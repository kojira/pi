# Claude Agent SDK structured Pi carrier (experimental)

Opt-in trial for a newly started Pi session. It does not change Pi's default model, credentials, or Gateway executable. Image input/tool results, selected thinking levels, and resuming a session created with this version are supported. It is not a drop-in replacement for other models; compaction, earlier prototype sessions, and mid-session model changes still have the restrictions below.

Install this example's pinned dependency with pnpm 11.14.0 (pinned in this directory's `packageManager` and `.mise.toml`; the root project is pinned to the same pnpm 11 version). This directory has its own 7-day `.npmrc` policy. pnpm 11 checks even *frozen lockfile* entries against that policy; CI runs both root and standalone installs. Then load it explicitly:

```sh
cd packages/coding-agent/examples/extensions/claude-sdk-structured
pnpm install --ignore-workspace --frozen-lockfile --ignore-scripts
cd ../../../../..
pi -e ./packages/coding-agent/examples/extensions/claude-sdk-structured/index.ts
```

Select `claude-sdk-structured/claude-opus-5-5` only after logging in to the **unmodified official Claude Code CLI** as the same individual account. The extension reads only the CLI's login status; it does not extract OAuth credentials or fall back to API-key billing. It refuses `ANTHROPIC_API_KEY` and `ANTHROPIC_AUTH_TOKEN` environment overrides. The displayed zero API cost is **not** free subscription usage; the subscription allowance is still consumed.

SDK tools and ambient settings are disabled. A structured result proposes **one** Pi tool call per turn; Pi's existing dispatcher validates and executes it. A finish/wait decision remains subject to Pi's work contract. An abort, unknown tool, inconsistent result, changed system prompt/tool list/context, unsupported image media type, or uncheckpointed old session fails closed. The resident SDK query is closed on session shutdown. A Pi assistant response carries the SDK session ID and system-prompt fingerprint; the official SDK persists its transcript under the signed-in account for resumed sessions. A model created by the previous version has no checkpoint and cannot be resumed retroactively. Pi thinking `off` disables SDK thinking; supported levels use SDK adaptive thinking and matching effort. **Discord selection:** In a newly registered channel with no history, select `claude-sdk-structured/claude-opus-5-5` with `/pi model`, then send a text prompt. For an existing channel, wait until all work and background children have finished; `/pi stop` closes its retained RPC connection, then `/pi new` archives the previous conversation and creates an empty session, then `/pi model` selects Claude. Do **not** stop or reset an active channel; do not silently discard an existing transcript. Gateway launches Pi with `--continue`, so selecting Claude on a non-empty transcript is rejected *before* an SDK request. A mid-session model switch also fails closed.

For a Gateway-managed `ch_<Discord channel ID>` session, the SDK input identifies the current channel and the existing `piscord send --channel ... --file ...` CLI. When the user requests a file attachment, Opus can propose Pi's `bash` tool to invoke that CLI; Pi remains the executor. The CLI must already be installed and configured on the host. The note is added to each SDK input, not the system prompt, so existing session checkpoints remain valid; standalone/non-channel sessions receive no channel hint. A successful model proposal is not evidence of actual delivery: check the CLI result before claiming the file was posted.

Pi compaction and branch summaries with this model return an explicit error without destroying the active SDK conversation; switch to a supported model before summarizing. A failed SDK request still reports an error for that request, but the next Pi request creates a fresh SDK carrier in the same Pi session. It resumes from an exact committed SDK checkpoint with the same prompt/tool catalog, skipping only this provider's empty failed responses; no Pi tool is re-executed. If no checkpoint exists, only user inputs and empty provider errors can start a new SDK session. Abort, model switches, and ambiguous histories remain fail-closed. Steer, context mutation, and multiple concurrent actions are not yet proven equivalent to the default model. Pi owns tool execution.

The adapter changes only two Pi documentation instructions in the SDK request while retaining Pi identity and document paths. If those source instructions change, it refuses to run rather than silently dropping them. This is a legitimate prompt presentation adjustment, not a credential or client-identity change.

One isolated five-response Opus 5.5 Pi session succeeded (`read` → four `finish_work` decisions). The second response wrote **54,985** 1-hour cache tokens and read **2,683**; responses 3–5 each read **over 99%** of their input from cache. Cache read exceeded 99% from response three in that one resident session, but subscription allowance consumption is not directly measurable from SDK token usage. For a real channel, expose this model **only as an optional trial**, require a fresh empty Pi session on first use, and retain the existing default and rollback path.

**Prototype limit removed:** SDK `maxTurns: 1` stopped a real image-reading task before a Pi decision; the SDK's internal model rounds are not Pi tool proposals. The arbitrary SDK turn, estimated USD, and 100-response trial caps have been removed. This changes no credential route: only the official signed-in Claude Code account is used; its own usage limits still apply. SDK cost estimates are not actual charges or subscription limits. Compaction, steer, and ambiguous failed-turn recovery remain unsupported.
